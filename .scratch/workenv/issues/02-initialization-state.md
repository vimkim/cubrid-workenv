# 02: 재초기화·중단·동시 초기화의 안전한 처리

**What to build:** 이미 준비된 환경은 그대로 유지하고, 준비 도중 실패하거나 동시에 init이 들어와도 사용자가 현재 상태와 다음 조치를 알 수 있게 한다.

**Blocked by:** 01

**Status:** ready-for-agent

Parent: [구현 명세](../spec.md)
User stories: 7, 8, 15

## Acceptance criteria

- [ ] 정상 환경에서 init을 다시 실행하면 이미 초기화되었다고 경고하고 성공 종료한다. 옵션을 바꿔도 DB·설정·할당을 변경하지 않는다.
- [ ] 가벼운 검사에서 손상이나 누락을 발견하면 실패 상태와 doctor 안내를 제공한다. 단순 반복 init으로 자동 repair나 resource 재배정을 하지 않는다.
- [ ] 할당 이후, 설정 생성 이후, DB 준비 이후의 실패를 유도해 불완전 상태와 작업 단서가 남는지 검증한다. 준비 완료 환경을 잘못 노출하지 않는다.
- [ ] 실패 후 다음 init은 불완전 상태를 설명하고 자동 재시도·삭제·rollback 없이 종료한다. 이 상태를 읽고 설명하는 최소 doctor 동작도 제공하여 안내가 실제로 동작하게 한다.
- [ ] 동일 worktree의 동시 init은 중복 DB 생성·설정 쓰기를 하지 않는다. 서로 다른 worktree의 동시 init은 같은 자원을 둘 다 할당받지 않는다.
- [ ] 할당 잠금은 짧은 배정 갱신 범위에 한정하고 서로 다른 worktree의 장시간 DB 작업이나 테스트를 직렬화하지 않는다.
- [ ] 반복 호출 전후 내용 비교, 별도 프로세스의 동시 호출, 실패 유도 후 재호출로 외부 동작을 검증한다.

## Scope and context

doctor의 전체 resource·DB·소유자 진단은 06에서 확장한다. 정확한 자료구조나 내부 함수 호출 순서를 테스트 계약으로 고정하지 않는다.

[용어집](../../../GLOSSARY.md)과 [native 중복 실행 실험](../../../experiments/native-db-exclusion/README.md)의 용어·검증 제한을 따른다. 공유 DB의 정상 경로 중복 열기는 CUBRID에 맡기고, init의 자원 할당 직렬화와 DB runtime 잠금을 혼동하지 않는다.
